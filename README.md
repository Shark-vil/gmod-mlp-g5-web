# Maretime Bay — сервис статистики (необязательный)

> Сервис для GMod-аддона [gmod-mlp-g5-addon](https://github.com/Shark-vil/gmod-mlp-g5-addon) — без файлов мода. Аддон сам
> отправляет сюда отчёты и читает открытые предметы; менять API — согласованно с ним.

Небольшой сервис (FastAPI + SQLite), куда игровые серверы GMod присылают копию статистики игроков:
звёзды за всё время, коллекцию, изученные заклинания, сыгранных персонажей, время в игре, а позже —
победы в мини-играх. Сохранения игроков всегда живут на самом игровом сервере (SQLite GMod);
если сервис недоступен или его больше нет — игра ничего не теряет и не выдаёт ошибок, данные просто
ждут в очереди.

## Запуск

```sh
cp .env.example .env      # всё необязательно; MLP_ADMIN_STEAMIDS — ваш SteamID64 (админ)
docker compose pull       # готовый образ ghcr.io/shark-vil/gmod-mlp-g5-web:latest
docker compose up -d      # сервис на порту MLP_PORT (по умолчанию 8080)
```

Обновление: `git pull && docker compose pull && docker compose up -d` (собирать на сервере не нужно). Образ собирает
GitHub Actions (`.github/workflows/docker.yml`) на каждый пуш в `main` — `latest`, `sha-<коммит>` — и на тег
`v1.2.3` — `1.2.3`, `1.2`; перед публикацией образ запускается и должен ответить на `/health`. Пакет в GitHub
Container Registry сначала приватный: сделайте его публичным (Packages → gmod-mlp-g5-web → Package settings →
Change visibility) или войдите на сервере `docker login ghcr.io` с токеном `read:packages`. Свой образ —
`MLP_IMAGE=…` в `.env`; собрать из исходников здесь же — `docker compose up -d --build`.

Страница рекордов — `/`. Вход на сайт — через Steam (OpenID: сайт получает только SteamID64, ник и аватар берёт с публичного профиля). Документация API (`/api/docs`) и админ-запросы — только для админов: SteamID64 в `MLP_ADMIN_STEAMIDS`, после входа через Steam. `MLP_PUBLIC_URL` — адрес сайта для ссылки возврата из Steam. Официальный адрес, который мод использует по
умолчанию: `https://gmod-mlp-g5.itpony.pro`.

**Песни игроков для «Танца»** (вход через Steam обязателен): `POST /api/v1/songs` (файл до 40 МБ и 5 минут,
название, исполнитель) — сервер перекодирует трек в ogg без метаданных (ffmpeg) и хранит его всегда (автор
может вернуться и поправить ноты без повторной загрузки), в фоне находит темп и сетку долей (librosa);
ноты автор ставит сам, автоматическая расстановка (`app/chart_auto.py` — те же правила, что у скрипта мода) — только
по кнопке «Расставить автоматически» (`POST …/auto`). «Очистить все ноты» — с подтверждением; черновик можно сохранить
без нот, мод — нет. У песни две копии: **рабочая** (её правит автор:
черновик → мод собран → на проверке → одобрена / отклонена) и **опубликованная** (последняя одобренная — её
видят все на `/songs` и берут игровые серверы); «Изменить» у одобренной песни открывает новую версию, а
опубликованная остаётся в игре, пока админ не одобрит новую. Полный трек слушают только автор и админы,
остальным — фрагмент. Лимиты — `MLP_SONG_*` в `.env`; файлы лежат рядом с базой (`/data/songs/<uuid>/`).
Если перед сайтом стоит nginx — поднимите `client_max_body_size` (например, `50m`), иначе загрузка оборвётся.

**Песни в игре:** игровые серверы берут опубликованные песни `GET /api/v1/songs/game` (ноты, направления, номер мода,
SHA256 файлов мода) раз в 10 минут; игра игрока сама скачивает мод песни из Мастерской, сверяет хеши и подключает
только звук (Lua мода не выполняется). Нужен включённый `mlp_api_enabled` на сервере.

**Страницы:** `/` — рекорды; `/songs` — общий список песен (поиск, фрагмент, автор, мод в Мастерской),
`/songs/<uuid>` — страница песни; `/admin` — админка (очередь проверки с полным треком, одобрить / отклонить с
причиной, все песни с поиском и фильтром, удаление, бан автора, «Запрещённые слова» — список «по строкам /
через запятую / по одному» с загрузкой `.txt`: песни с такими словами в названии / исполнителе скрываются); `/my-songs` — «Мои песни» (загрузка, список своих песен со статусами, редактор, удаление
неопубликованной); `/me` — «Моя статистика» (свой профиль с графиками); `/editor/<uuid>` — редактор нот песни: волна звука, сетка ударов с
привязкой, поставить / сдвинуть / удалить ноту, удержания, направление ноты (↑ ↓ ← → E или 🎲 — случайная
в каждой игре; в данных песни поле `keys`; режимы «Кисть» — новые ноты получают выбранное направление — и «Правка» —
кнопки меняют выбранные ноты), выбор нескольких нот (Shift+клик / Shift+протянуть / Ctrl+A), Alt+клик — стереть,
Ctrl+клик — следующее направление, Q / B / 1–5 / 0, Shift+←→ — сдвиг на шаг привязки, Ctrl+C / Ctrl+V — копия
с места курсора, Ctrl+Y — вернуть, Ctrl+S — сохранить, X — зеркало выбранных (← ↔ →, ↑ ↔ ↓), F — заполнить по
сетке между первой и последней выбранной, M — метроном, скорость 1× / 0,75× / 0,5× (полный список — в карточке
«Как править»), обрезка песни (`POST …/trim`: кусок загруженного исходника, ноты
сдвигаются вместе с ним, «Вся песня» возвращает всё), Live-запись («● Запись»: песня играет, нажатия в такт
становятся нотами с направлением, дольше ~0,6 с — удержание; привязка к сетке, поправка задержки, замена нот
в записанном отрезке, одна отмена на всю запись), обложка (из аудиофайла, своя — `POST …/cover`, или заглушка;
она же значок мода), отмена, «Расставить автоматически», фрагмент для
прослушивания, «Проверить» (та же ритм-игра, что в моде), «Сохранить» (`PUT /api/v1/songs/<uuid>/chart`: ноты
не ближе 0,25 с, после удержания 2 с свободно, превью 10–30 с внутри песни). Общие файлы — `static/site.css`,
`static/site.js` (вход), `static/stats.js` (каталог показателей, профиль, графики).

**Мод песни и Мастерская.** «Собрать мод» (`POST …/build`) замораживает черновик: сайт собирает
`lua/mlp_g5_songs/<uuid>.lua` (данные песни — JSON в длинной строке Lua, мод читает его как текст и не
выполняет) и `sound/mlp_g5/songs/<uuid>.ogg`, запоминает их SHA256 (игра сверяет скачанное с ними).
`GET …/mod.zip` — архив: эти файлы, `addon.json`, `icon.jpg` (512×512) и `README.txt` (как проверить и выложить
через `gmad` / `gmpublish`). Ссылку на мод автор вставляет в редакторе (`POST …/submit`): сайт спрашивает
Steam (`GetPublishedFileDetails`, без ключа) — предмет существует, это Garry's Mod, автор — вошедший аккаунт,
не забанен, не привязан к другой песне — и отправляет песню на проверку (`pending`). `POST …/unbuild` — назад к
правке (мод придётся собрать заново). `MLP_PUBLIC_URL` попадает в данные песни как ссылка на сайт.

**Ключи никому выдавать не нужно.** Отчитываться может любой сервер с модом — и выделенный, и одиночная
игра игрока (он сам себе сервер). Каждая установка GMod при первом запуске придумывает себе случайный
`X-Install-Id`; по нему считаются лимиты и его можно удалить целиком. `MLP_SERVER_KEYS` — необязательно,
для своих доверенных серверов.

## Важно про локальный адрес

GMod не пускает HTTP-запросы на локальные адреса (127.0.0.1, 192.168.*, localhost). Если сервис
стоит на той же машине или в той же сети, что и выделенный сервер GMod, запускайте сервер с параметром
`-allowlocalhttp`. Для обычного случая (сервис на внешнем хостинге с доменом) ничего не нужно.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/v1/nonce?purpose=report` | одноразовый токен для следующего POST (`report` или `unlocks`), живёт `MLP_NONCE_TTL` (5 с) |
| POST | `/api/v1/report` | отчёт сервера (заголовки `X-Install-Id`, `X-Nonce`, `X-Sign`; необязательно `X-Server-Key`) |
| GET | `/api/v1/leaderboard?stat=stars&limit=20` | таблица по статистике |
| GET | `/api/v1/items/leaderboard?kind=vanity` | таблица по открытым предметам (`vanity`, `spell`) |
| GET | `/api/v1/player/{steamid64}` | профиль игрока |
| GET | `/api/v1/unlocks/{steamid64}` | открытые предметы и заклинания игрока со всех серверов |
| POST | `/api/v1/unlocks` | то же для всего сервера одним запросом (с `X-Nonce` / `X-Sign`): `{ "steamids": [ … до 128 ] }` → `{ "players": [ { "steamid", "vanity", "spell" } ] }` |
| GET | `/api/v1/stats/keys` | какие статистики есть |
| GET | `/api/v1/admin/flags` | что было обрезано / отклонено (заголовок `X-Admin-Token`) |
| DELETE | `/api/v1/admin/player/{steamid64}` | стереть игрока (накрутчика) целиком |
| DELETE | `/api/v1/admin/install/{id}` | стереть всё, что прислала одна установка |
| GET | `/health` | проверка живости |

Отчёт: `{ "version": 1, "server": { "name", "map" }, "players": [ { "steamid", "nick", "playtime",
"stats": { ключ: число }, "items": { вид: количество }, "characters": [ … ],
"unlocked": { "vanity": [ id… ], "spell": [ id… ] } } ] }`.

Сложение между серверами: обычные счётчики суммируются, `best_*` — максимум, `time_*` — минимум.

## Защита от накрутки (только от очевидного)

Без ключей и авторизации защититься от всего нельзя: любой может прислать отчёт от имени любого SteamID.
Сервис отсекает только явные накрутки:
- лимиты запросов считаются **на установку** (`MLP_RATE_PER_MIN`, `MLP_LOOKUP_PER_MIN`): сервер на 128 игроков —
  одна установка, он шлёт отчёты и запросы предметов пачками. На IP — только защита от флуда
  (`MLP_IP_RATE_PER_MIN`, по умолчанию 300/мин), ведь за одним IP может быть большой сервер, хостинг с
  несколькими серверами или игроки за NAT; новых установок с одного адреса — до `MLP_NEW_INSTALLS_PER_IP_DAY`
  (20) в сутки;
- счётчик одной установки растёт не быстрее разумного темпа с её прошлого отчёта, а у игрока по всем
  установкам вместе — не больше суточного лимита (звёзды 2500, победы 300 и т. д.): новые установки
  не размножают прибавку;
- новая установка начинает с небольшого запаса (300 звёзд, 1 час игры), а не с суточного лимита — один
  запрос не принесёт сразу всё; давний игрок догрузит своё за несколько отчётов;
- каждый POST требует одноразовый токен (`GET /api/v1/nonce`, 5 секунд — `MLP_NONCE_TTL`, для одной установки и одного
  вида запроса) и подпись `SHA256( токен + тело + соль )`. Соль открыта в коде мода, так что это не защита,
  а усложнение: руками из браузера не отправить, старый запрос не повторить;
- невозможные рекорды трасс (`time_*` быстрее нескольких секунд) не принимаются;
- открытые предметы проверяются: всего не больше `3 + минуты игры / 5`; предмет «за звёзды» — только при
  достаточном числе звёзд, заклинание —
  только при известном заклинании ступенью ниже, неизвестные предметы — нет, не больше 16 предметов и
  5 заклинаний в сутки на игрока (остальное догрузится следующими отчётами);
- всё обрезанное и отклонённое пишется в `flags`; админ (вход через Steam из `MLP_ADMIN_STEAMIDS`, или старый `MLP_ADMIN_TOKEN` для скриптов) видит их и может стереть
  игрока или установку.

Локальная проверка без Docker: `MLP_DB=./data/stats.db uv run --with fastapi --with uvicorn uvicorn app.main:app --port 8765`.
